# 轨迹场景语义标注 plan（探索验证）

## 文档状态

- 状态：进行中
- 建立日期：2026-10-08
- 适用范围：在半离线历史轨迹上做场景语义标注的可行性验证；**不做 RL**
- 性质：探索/验证阶段任务。链路确认可用后再决定是否整理为稳定模块。

## 1. 目标与研究意图

在现有半离线项目（HA-SODQN / Plan 1 轨迹资产）基础上，为后续"场景引导的注意力机制"建立语义层。本阶段只验证表征链路：

- 从历史轨迹恢复观测窗口；
- 由窗口统计生成事实描述文本；
- 冻结预训练语义模型编码事实描述，产出内部语义向量；
- 外部人语义文本（如"某路口堵塞"类场景描述）经同一编码器产出外部向量；
- 验证内外向量可匹配（轨迹观测能够产出与外部文本对齐的语义数据）。

通过判定后才进入场景引导注意力的设计，不在本阶段讨论训练。

## 2. 已确认的 design decisions（2026-10-08）

| 决策点 | 结论 |
| --- | --- |
| 场景定义 | 跨路网可共享的**运行模式词表**（潮汐方向、需求失衡形态、拥堵位置等），非路网身份；标注粒度为窗口级 |
| 外部文本口径 | 人语义场景描述（如"某路口堵塞"类自然语言），非现有事件报告模板 |
| 描述素材边界 | **仅 16 维策略观测**（8 进口车道计数 + 8 相位 one-hot）；npz 中 queue/delay/throughput 诊断字段不进描述，保留日后入策略的无泄漏性 |
| 匹配验证口径 | 三层都要：检索对齐（top-k 命中）+ 聚类一致性 + 可分性 probe |
| 编码器 | 复用 `reproduction/tarl_tsc/text/encoder.py` 的 FrozenTextEncoder + 本地 bert-base-uncased 资产（内外同一编码空间是匹配前提） |

## 3. 数据源

- Plan 1 正式轨迹：`data/output_data/tsc/sumo_dqn/sumohz1x1{,_config2,_config3,_config4}/p1_formal_dqn_*_r2`，白名单 20 run × 400 ep 已核验在位；
- 每 episode npz：360 个 decision（interval=10s），字段含 `state`(360,1,1,8)、`current_phase`(360,1,1)、`action`、`reward` 等；
- 首轮仅用 S1–S4 的 Plan 1 数据；arterial 1×6 暂不纳入。

## 4. 流水线

```
npz 轨迹 ──► 滑窗恢复（窗口长 W、步长 S，单位=decision）
        ──► 窗口统计（各向车道计数水平/趋势/失衡度/相位占比）
        ──► 模式词表（先聚类/枚举真实形态，再定词表与人语义锚点描述）
        ──► 事实描述模板生成（观测统计→受控文本）
        ──► FrozenTextEncoder 编码（z_internal 与外部文本 z_external 同空间）
        ──► 三层匹配验证
```

## 5. 阶段分解

| 阶段 | 内容 | 产出 |
| --- | --- | --- |
| P0 | 窗口恢复器 + 统计 dump（最小抽样，先几百集） | 窗口统计表、形态观察 |
| P1 | 模式词表 + 人语义锚点描述草案 | 词表 v0（待用户审） |
| P2 | 事实描述模板生成器 + 冻结编码 | 事实描述样例、embedding |
| P3 | 三层匹配验证 | 检索命中率 / 聚类一致性 / probe 可分性报告 |
| P4 | 判定：若通过，整理为稳定模块（候选 `dataset/` 或 `generator/` 下），供注意力线消费 `SceneCondition` 槽位 | 归档或转正 |

## 6. 落点与治理

- 探索脚本：`dev/scene_semantics/`，登记 `dev/INDEX.md`；
- 标注产物：`data/output_data/scene_semantics/`（不进 git）；产物需带 manifest（源 run、窗口参数、模板版本、encoder hash）；
- 不改动 `sequential/`、`agent/`、`world/` 现有模块；若 P4 转正另议；
- 本阶段不登记 `ledger/runs.jsonl`（非训练/评估 run）；若 P3 形成正式验证批次再按治理口径补登记。

## 7. 规模与时间开销（本机 RTX 4060 Ti + 24C + 62G 实测口径）

- 最小闭环（抽样 ~400 ep → ~2 万窗口 → 几十条锚点文本）：端到端计算在十分钟量级；
- 全量 Q1（2000 ep、72 万 transition → ~10 万窗口）：P0 I/O 约 5–15 分钟，编码 <10 分钟，评估分钟级；
- 产物磁盘：<1GB（embedding ~10 万 × 768 × 4B ≈ 300MB 上限）。

## 8. 验证口径与判定

三层全部报告，不单独取有利项：

1. **检索对齐**：轨迹事实描述 embedding 对锚点集最近邻检索的 top-1/top-k 命中率；
2. **聚类一致性**：内部 embedding 按模式自然分簇，外部文本落对应簇；
3. **可分性 probe**：embedding 上浅层分类器的模式可分性。

通过标准在 P3 开始前写定（当前不预设阈值）。

## 9. 风险与边界

- 16 维观测信息有限（8 车道计数+相位），模式词表可分性上限受观测约束；P0/P1 先确认观测中确实存在可区分的模式形态；
- 事实描述模板与人语义锚点的措辞差异本身会影响匹配——这是要验证的内容，不是可假设成立的前提；
- 本阶段产出只证明"轨迹→语义"链路可用，不构成注意力机制有效的证据。
